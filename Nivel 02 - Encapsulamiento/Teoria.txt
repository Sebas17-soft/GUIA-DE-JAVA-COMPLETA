1. PORTADA Y MISIÓN DEL NIVEL
--------------------------------------------------------------------------------
- Pregunta guía: ¿Cómo evito que nadie descuadre la caja?
- Contexto de Café Sintaxis:
  En el nivel 1 los atributos eran accesibles directamente por cualquiera. Martín descubrió
  que un error tipográfico o una asignación descuidada podía poner un saldo negativo o
  cambiar el precio de un producto sin control. Valeria exige blindar la caja para que
  ningún valor inválido pueda entrar al sistema.
- Objetivos de aprendizaje:
  1. Comprender y aplicar los cuatro niveles de acceso en Java, con énfasis en private y public.
  2. Implementar encapsulamiento estricto: atributos privados y métodos públicos con validación.
  3. Comprender el concepto de invariante de clase y protegerlo mediante excepciones (IllegalArgumentException).
  4. Utilizar `this` para desambiguar atributos de parámetros (shadowing).
  5. Distinguir entre métodos de consulta (getters) y operaciones de mutación controlada.

2. SESIÓN 01 · DESCUBRE: DEFINICIONES OFICIALES Y REGLAS DE ORO
--------------------------------------------------------------------------------
Definiciones oficiales de Oracle (Java Tutorials & JLS Java SE 25):

- MODIFICADOR DE ACCESO:
  «Un modificador de acceso determina si otras clases pueden usar un campo particular
  o invocar un método particular.»

- PRIVATE:
  «El modificador private especifica que el miembro solo puede ser accedido en su propia clase.»

- REGLA DE ORO DEL ENCAPSULAMIENTO:
  «Usa el nivel de acceso más restrictivo que tenga sentido para un miembro en particular.
  Usa private a menos que tengas una buena razón para no hacerlo.»

Analogía con la cafetería:
La caja registradora tiene una ranura para ingresar billetes y botones para cobrar
(interfaz pública), pero el cajón donde se almacena el dinero físico está cerrado bajo
llave (estado privado). Nadie puede meter la mano directamente a mover el fajo de billetes;
todo movimiento debe pasar por una operación autorizada que valida y registra la transacción.

Vocabulario clave:
- private: modificador que oculta miembros a cualquier clase externa.
- public: modificador que hace accesible un miembro desde cualquier lugar.
- Invariante de clase: condición o regla de negocio que debe permanecer verdadera durante
  toda la vida útil del objeto (ej. saldo >= 0).
- Encapsulamiento: principio de agrupar datos y métodos que operan sobre ellos, restringiendo
  el acceso directo a los detalles internos de implementación.
- Getter: método público que retorna el valor de un atributo privado sin permitir su mutación.
- Setter: método público que recibe un nuevo valor, lo valida y, si cumple las reglas, muta el atributo.
- IllegalArgumentException: excepción estándar que se lanza cuando un método recibe un argumento no válido.

3. SESIÓN 02 · COMPRENDE: TABLA DE VISIBILIDAD E INVARIANTES
--------------------------------------------------------------------------------
Tabla comparativa de modificadores de acceso en Java:

┌───────────────┬─────────┬─────────┬──────────┬───────┐
│ Modificador   │ Clase   │ Paquete │ Subclase │ Todos │
├───────────────┼─────────┼─────────┼──────────┼───────┤
│ private       │ SÍ      │ NO      │ NO       │ NO    │
│ (paquete)     │ SÍ      │ SÍ      │ NO       │ NO    │
│ protected     │ SÍ      │ SÍ      │ SÍ       │ NO    │
│ public        │ SÍ      │ SÍ      │ SÍ       │ SÍ    │
└───────────────┴─────────┴─────────┴──────────┴───────┘

Invariante y Fallos Rápidos (Fail-Fast):
Al validar en la entrada de métodos con `throw new IllegalArgumentException(...)`, el programa
rechaza datos corruptos en el mismo instante en que se intentan introducir, evitando que
el estado interno del objeto se degrade silenciosamente.

4. SESIÓN 03 Y 04 · ANÁLISIS DE CÓDIGO Y DECISIONES DE DISEÑO
--------------------------------------------------------------------------------
Diseño de Caja.java:
- `saldo` y `ventas` son `private`.
- No existe `setSaldo(int)`: el saldo solo puede aumentar mediante `cobrar(int valor)`
  o disminuir mediante `retirar(int valor)`.
- Si `valor <= 0` en `cobrar`, se lanza excepción y `saldo += valor` nunca se ejecuta.

Diseño de Producto.java (Solución de Julián):
- Uso de `this.nombre = nombre;` y `this.precio = precio;`.
- El prefijo `this` hace referencia explícita al atributo de la instancia actual, diferenciándolo
  del parámetro formal que posee el mismo nombre (sombreado de identificadores).
- `setPrecio` valida el rango: `0 <= precio <= 50000`.

5. SESIÓN 05 · CONECTA: ENCAPSULAMIENTO EN LA INDUSTRIA
--------------------------------------------------------------------------------
- Bibliotecas estándar como `java.util`: Los campos de clases como `ArrayList`, `HashMap` o `String`
  son rigurosamente privados. Si fueran públicos, cualquier usuario podría modificar la longitud
  o los punteros internos, causando caídas catastróficas.
- Mantenibilidad: Ocultar los detalles internos permite al autor cambiar la implementación
  (por ejemplo, pasar de guardar pesos a guardar centavos o cambiar una estructura de datos)
  sin romper el código de los clientes que usan la clase.

6. SESIÓN 08 · COMPRUEBA: EVALUACIÓN COMPLETA, RESPUESTAS Y JUSTIFICACIONES
--------------------------------------------------------------------------------
PREGUNTA 1 (Opción múltiple · DOK 1 · 3 XP):
¿Qué modificador deja un atributo visible solo dentro de su propia clase?
  a) public
  b) protected
  c) private
  d) static
RESPUESTA CORRECTA: c) private
JUSTIFICACIÓN:
Por definición del lenguaje Java, el modificador `private` restringe la visibilidad
del miembro exclusivamente al cuerpo de la clase en la que fue declarado.

PREGUNTA 2 (Verdadero o Falso · DOK 1 · 3 XP):
"Un getter permite que otra clase cambie el valor del atributo privado."
  [V]  [F]
RESPUESTA CORRECTA: FALSO (F)
JUSTIFICACIÓN:
Un getter (método accesor) solo devuelve una copia o lectura del valor; no contiene
ninguna lógica de asignación ni mutación de estado.

PREGUNTA 3 (Relaciona · DOK 2 · 3 XP):
Relaciona cada pieza con su función:
  - private      ---> Esconde el dato
  - getSaldo()   ---> Consulta sin cambiar
  - throw        ---> Rechaza un dato inválido
  - catch        ---> Responde al error
JUSTIFICACIÓN:
`private` oculta el campo; `getSaldo()` retorna el valor sin modificarlo; `throw` interrumpe
el flujo ante un estado no válido; y `catch` captura la excepción para controlarla.

PREGUNTA 4 (Ordena · DOK 2 · 3 XP):
Ordena el método cobrar de la caja:
  [1] Recibir el valor
  [2] Revisar si es 0 o menos
  [3] Lanzar la excepción si lo es
  [4] Sumar al saldo
  [5] Contar la venta
JUSTIFICACIÓN:
El flujo de validación defensiva evalúa primero los parámetros recibidos. Si el valor
es incorrecto, se lanza la excepción inmediatamente (fail-fast), interrumpiendo el método
antes de alterar el saldo o el contador de ventas.

PREGUNTA 5 (Opción múltiple · DOK 2 · 3 XP):
El compilador dice: "saldo has private access in Caja". ¿Qué arreglo respeta el encapsulamiento?
  a) Cambiar a public int saldo
  b) Usar caja.cobrar(…) o getSaldo()
  c) Borrar el atributo
  d) Quitar private de la clase
RESPUESTA CORRECTA: b) Usar caja.cobrar(…) o getSaldo()
JUSTIFICACIÓN:
La solución correcta respeta el diseño seguro: en lugar de debilitar el acceso abriendo
el campo, el llamador debe interactuar a través de los métodos públicos provistos por la clase.

PREGUNTA 6 (Respuesta abierta · Analizar · DOK 3 · 5 XP):
En el setter, ¿qué pasa si escribes `precio = precio;` en lugar de `this.precio = precio;`? Explica.
RESPUESTA Y JUSTIFICACIÓN:
Ocurre un sombreado de variable (variable shadowing). El nombre `precio` dentro del método
se refiere exclusivamente al parámetro local recibido. La línea `precio = precio;` simplemente
asigna el parámetro a sí mismo, dejando el atributo de instancia `this.precio` intacto con su
valor previo, provocando un fallo lógico silencioso.

PREGUNTA 7 (Respuesta abierta · Evaluar · DOK 3 · 5 XP):
Martín propone un setSaldo(int) público «por si acaso». ¿Lo aceptas? Justifica con el invariante de la caja.
RESPUESTA Y JUSTIFICACIÓN:
NO se acepta de ninguna manera. Un método `setSaldo(int)` destruiría por completo el
invariante de la caja registradora, ya que permitiría a cualquiera sobreescribir el dinero
existente con cualquier cifra (incluso negativa o descuadrada) sin dejar registro de si
fue una venta o un retiro, arruinando la trazabilidad y la integridad financiera del negocio.

PREGUNTA 8 (Respuesta abierta · Crear · DOK 3 · 5 XP):
Escribe la clase Termo con litros privados, servir(int ml) que rechace pedir más de lo que hay, y su getter.
RESPUESTA Y CÓDIGO:
```java
public class Termo {
    private int litros; // medido internamente en ml para precisión

    public Termo(int litrosIniciales) {
        if (litrosIniciales < 0) throw new IllegalArgumentException("Litros inválidos");
        this.litros = litrosIniciales * 1000;
    }

    public void servir(int ml) {
        if (ml <= 0) throw new IllegalArgumentException("Cantidad inválida");
        if (ml > litros) throw new IllegalArgumentException("No hay suficiente café");
        litros -= ml;
    }

    public int getLitros() { return litros / 1000; }
}
```

7. CIERRE DEL NIVEL 02 · METACOGNICIÓN
--------------------------------------------------------------------------------

- Mapa conceptual:
  Clase Encapsulada
    ├── Atributos privados (private int saldo; private int ventas;)
    ├── Validaciones de negocio (if (...) throw new IllegalArgumentException(...))
    ├── Acceso de lectura (getters públicos)
    └── Operaciones de mutación seguras (cobrar, retirar)
- Insignia obtenida: «Guardián/a de la caja».
- Explicación en 60 segundos:
  "El encapsulamiento consiste en proteger el estado interno de un objeto haciéndolo privado
  y exponiendo únicamente operaciones públicas controladas. Así, la clase garantiza que sus
  datos siempre sean coherentes y válidos, impidiendo que código externo los corrompa o descuadre."
